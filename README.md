# Мониторинг Telegram-чатов для швейных заказов

Система слушает новые сообщения в выбранных группах и каналах через **один личный Telegram-аккаунт**. Если текст или подпись к медиа подходит под активное правило, в целевую группу отправляется **одно сообщение**: исходный текст, пустая строка и кликабельная ссылка для связи. Для фото и файлов используется подпись того же сообщения. Формат меняется в Django Admin с темой Jazzmin.

## Быстрый запуск на сервере

Нужны Docker и Docker Compose. Сервер должен иметь исходящее соединение с Telegram; порт `8080/tcp` должен быть доступен для администратора.

1. Скопируйте `.env.example` в `.env`.
2. В `.env` заполните:
   - `SERVER_IP` в `DJANGO_ALLOWED_HOSTS` и `DJANGO_CSRF_TRUSTED_ORIGINS` своим IP. Например: `DJANGO_ALLOWED_HOSTS=127.0.0.1,203.0.113.10` и `DJANGO_CSRF_TRUSTED_ORIGINS=http://203.0.113.10:8080`.
   - `DJANGO_SECRET_KEY`: `python -c "import secrets; print(secrets.token_urlsafe(50))"`.
   - `TELEGRAM_SESSION_KEY`: `python -c "import base64,secrets; print(base64.urlsafe_b64encode(secrets.token_bytes(32)).decode())"`.
   - `POSTGRES_PASSWORD` и `DJANGO_SUPERUSER_PASSWORD`: собственные сильные пароли.
   - `TELEGRAM_API_ID` и `TELEGRAM_API_HASH`: получите в [my.telegram.org](https://my.telegram.org) → API development tools. Это данные приложения Telegram, а не токен бота.
3. Запустите `docker compose up -d --build`.
4. Откройте `http://IP:8080/admin/` и войдите под `DJANGO_SUPERUSER_USERNAME` / `DJANGO_SUPERUSER_PASSWORD`.

При первом старте веб-контейнер применяет миграции, собирает статику и создаёт администратора. Пароль существующего администратора при последующих стартах не меняется.

## Настройка

1. **Telegram-аккаунт** → **Подключение**: нажмите «Показать QR-код», затем на телефоне откройте Telegram → Настройки → Устройства → Подключить устройство и отсканируйте код. QR-код обновляется автоматически. Если включена двухэтапная проверка, введите её пароль. Вход по номеру и коду также доступен. Подключение нового аккаунта доступно после отключения старого. Для QR-входа должен работать контейнер `scanner`.
2. **Группы и каналы-источники**: добавьте группы и каналы, откуда нужно получать сообщения. Допускаются ID (`-100...`), `@username`, публичная ссылка `https://t.me/name` и пригласительная ссылка приватной группы или канала. Аккаунт должен **уже состоять** в каждом источнике. Система не вступает в них автоматически. Если источник не найден, причина появится в колонке «Ошибка подключения».
3. **Ключевые слова / фразы**: добавьте нужные выражения. Для каждого правила можно указать алиасы и исключающие фразы, по одной на строке. Например, фраза `ищу швею`, алиасы `нужна швея` и `требуются швеи`, исключение `курсы швей`.
4. **Целевая группа**: укажите одну группу по ID или ссылке. Аккаунт должен быть её участником и иметь право пересылать сообщения.
5. **Формат сообщений**: отредактируйте шаблон. Значение по умолчанию — `{text}`, пустая строка, `{contact}`. Переключатель «Показывать источник сообщения» добавляет строку с названием группы или канала в начале того же сообщения. Для собственного расположения источника используйте `{source}` в шаблоне. Доступно также `{keyword}`. Общая подпись контакта настраивается рядом; индивидуальная подпись и выбор контакта — в настройках источника. Telegram допускает максимум 4096 символов в текстовом сообщении и 1024 в подписи медиа; слишком длинный результат будет отмечен ошибкой в журнале.
6. **Журнал пересылок**: показывает сработавшее правило, статус и ошибку Telegram при неудачной отправке.

Изменения правил, источников, разбора описания, контактов и формата применяются фоновым процессом в течение ~20 секунд. Обрабатываются новые сообщения с момента работы сканера; старую историю система не копирует. Сообщение отправляется заново, поэтому нативной отметки Telegram «Переслано от…» нет; при включении видимости источник показывается строкой в тексте. Выделенное описание и его форматирование сохраняются внутри настраиваемого шаблона. Контакт ведёт в личный аккаунт продавца или автора. Если подходящего контакта нет, его подпись остаётся обычным текстом без ссылки; ссылка на публикацию или канал не подставляется. Сообщения из источника с запретом копирования и типы вложений без текстовой подписи помечаются ошибкой в журнале. Система не отправляет сообщения из самой целевой группы, поэтому не создаёт цикл.

## Разбор описания для каждого источника

Откройте **Группы и каналы-источники → нужный канал → Разбор описания**. Каждый канал имеет собственные настройки. И ключевые слова (включая исключения), и журнал, и отправляемый текст используют только полученное описание. Пустой результат пропускается.

1. Выберите начальную и, при необходимости, конечную строку или число строк, отбрасываемых с конца. Нумерация с 1 по исходному тексту; пустые строки считаются, визуальный перенос длинной строки в Telegram — нет.
2. Для переменной длины заголовка/подвала задайте маркеры начала и конца, по одному на строке. Это буквальные фрагменты без учёта регистра. Строка с маркером начала не включается; первое совпадение с любым маркером конца обрывает описание перед этой строкой. Маркеры ищутся внутри выбранного диапазона строк. Если заданный маркер начала не найден, пост пропускается; если маркер конца не найден, используется остаток диапазона.
3. Настройте исключаемые строки. По умолчанию удаляются отдельные строки «Скрыт», «Разместить объявление», «Написать продавцу», «Добавить в избранное», «Профиль», в том числе с эмодзи. Можно изменить этот список или дополнительно удалять строки по вхождению фразы. Фразы внутри обычного описания при точном исключении не удаляются. Включённая по умолчанию опция скрытого текста удаляет строки со спойлерами Telegram (например, номер телефона).
4. Вставьте исходный пост в **Проверка разбора → Пример поста** и нажмите **Проверить разбор**. Показывается результат и исходные строки с номерами; настройки для проверки сохранять не требуется, сам пример не сохраняется. Вставленный текст не содержит форматирования Telegram, поэтому удаление спойлеров проверяется только на реальном сообщении. После проверки сохраните настройки канала.

Например, для поста `#techno`, строка статуса продавца, затем описание со строки 3 и цена отдельной строкой: укажите начало **3**, а маркеры конца **KGS** и **Телефон:** на отдельных строках. Если перед описанием три служебные строки и пустая строка, начало будет **5**. Конкретную границу проверяйте на примере; настройки одного канала не влияют на другие. Заголовки, цену и контакты нужно ограничить правилами своего источника — их формат не угадывается автоматически.

## Контакт продавца для каждого источника

В **Группы и каналы-источники → нужный канал → Контакт продавца / автора** доступны четыре режима:

- **Ссылка продавца из поста, иначе автор сообщения** (по умолчанию): сначала ищется подписанная ссылка продавца. Если её нет, используется личный аккаунт автора сообщения; канал или бот автором для связи не считается. Если ссылка продавца указана, но непригодна, она не заменяется контактом автора.
- **Только ссылка продавца из поста**: подходит для каналов объявлений. Без ссылки продавца подпись некликабельна.
- **Только автор сообщения**: подходит для групп, где автор сам размещает свой заказ.
- **Без ссылки (только подпись)**: контакт всегда отображается обычным текстом.

Поле **Подпись контакта** задаёт, например, «Написать продавцу» для этого канала. Если оставить пустым, используется общая подпись из «Формат сообщений». В поле **Как подписана ссылка продавца в исходном посте** перечислите допустимые подписи. Поддерживаются ссылки под текстом, URL-кнопки, кнопки профиля, упоминания пользователя и строки вроде `Продавец: @username`. Ссылки извлекаются из полного оригинала, даже если подвал удаляется при разборе описания. Обычная вставка текста в проверку разбора не переносит скрытые URL и кнопки Telegram.

Адрес проверяется через Telegram: он должен вести на личный аккаунт, а не на канал, группу, бота, публикацию или внешний сайт. Если адрес не удалось проверить, пост отправляется с некликабельной подписью. Кнопки ботов, работающие через callback или `?start=...`, не содержат прямой ссылки продавца и не используются. Для объявления со ссылкой «Написать продавцу» выберите режим **Только ссылка продавца из поста** и оставьте эту фразу в списке подписей.

## Как работает подбор

Текст приводится к нижнему регистру, `ё` заменяется на `е`, знаки препинания отделяются, русские слова приводятся к начальной форме. Поэтому `Ищем швей` подходит к правилу `ищу швею`. Алиасы позволяют добавить иные формулировки. Для слов длиной от шести символов допускается небольшая опечатка. Короткие слова сравниваются точно, чтобы снизить случайные совпадения. Исключающие фразы отменяют срабатывание конкретного правила. Это поиск по языковым правилам, не полноценная смысловая модель; необычные формулировки нужно добавлять как алиасы.

## Эксплуатация

```bash
docker compose ps
docker compose logs -f scanner
docker compose logs -f web
docker compose down
```

Данные хранятся в Docker-томе `postgres_data`. Для резервной копии нужны база PostgreSQL **и** ключ `TELEGRAM_SESSION_KEY` из `.env`: без него восстановить зашифрованную Telegram-сессию нельзя. Не публикуйте `.env`, дампы базы и логи с чувствительными данными.

HTTP на `8080` соответствует запрошенной схеме, но код Telegram и пароль администратора передаются по сети без шифрования. Для доступа через интернет рекомендуются HTTPS перед Nginx или ограничение порта VPN/фаерволом. При HTTPS добавьте `https://...` в `DJANGO_CSRF_TRUSTED_ORIGINS`.

## Локальная разработка

```bash
python -m venv .venv
# Активируйте окружение вашей ОС
python -m pip install -r requirements.txt
python manage.py migrate
python manage.py createsuperuser
python manage.py runserver
# В другом терминале после настройки .env:
python manage.py run_scanner
python manage.py test
```

Без `POSTGRES_DB` проект использует SQLite для локального запуска. Переменные из `.env` при таком запуске нужно загрузить в окружение самостоятельно; `docker compose` загружает их автоматически.
